## ما تحقق فعليًا

- 55 اختبارًا للمختبر و47 اختبارًا للخادم، واختباران لبروتوكول الأرشفة الخاصة.
- تشغيل Android API 32 حقيقي على مشغّل GitHub Actions قياسي، وتثبيت تطبيق الاختبار وأداة الكتابة.
- تشغيل apksigner وApktool وJADX داخل مستخدم أدوات منفصل، وإنشاء تقرير فعلي لتطبيق الاختبار مع حفظ بصمة الأصل.
- عرض شاشة Android عبر نفق HTTPS مؤقت والتحكم به من Chromium؛ تغيّرت شجرة الجهاز وبكسلات الشاشة بعد أمر Home فعلي.
- قناة مستقلة لأوامر مشفّرة عبر GitHub، مع التحقق من فتح الإعدادات والعودة للرئيسية ولقطات المحاكي.
- تشفير النتائج وإغلاق الجلسة والمُحاكي بعد الاختبار.
- توافق تشفير Python وCryptoKit في الاتجاهين، وفحص وحدات التحكم والعرض وأدوات المختبر باستخدام SDK فعلي لـiOS.
- فحص تخطيط واجهة الويب بمقاسي iPhone وiPad؛ هذا لا يعادل تجربة تطبيق ZEUS كاملًا على iPad.
- وضع الثقة للجلسة يلغي التأكيدات المتكررة الخاصة بالمختبر؛ استعادة التحكم تلغي الثقة. كلا المسارين له اختبار.
- قناة أولوية مستقلة لاستعادة التحكم عبر GitHub؛ اختُبر إلغاء أداة عالقة دون انتظار قفل الأدوات، ورفض أوامر الاستعادة غير المصرّح بها.
- رفع وتنزيل فعليان عبر أصول GitHub الخاصة، ثم استيراد ملف اختبار 27,263,308 بايت وأرشفته واستعادته مع تطابق SHA-256. ملف الاختبار مخصص للتخزين، وليس دليل تشغيل Android.
- الحفظ الخاص يدعم نقاط استعادة حتى1 GiB مضغوط، دوريًا وعند الإنهاء. لا تُدرج هوية توقيع APK الخاصة في الأرشيف. الاستعادة تتحقق من الأصل وتحفظ قاعدة الجلسة الحالية؛ السجل السابق يبقى داخل أرشيفه.
- تثبيت شهادة HTTPS داخل tmpfs على Android API32 دون إعادة تشغيل أو تعديل AVB. شوهد طلب HTTPS من التطبيق الحقيقي بمحتواه العربي؛ اختبار دورة الاستجابة والبناء المدمجة ما زال قيد التحقق.
- مشغّل H.264 فكّ إطارات فعلية من مصدر اصطناعي داخل Chromium، واجتاز تحويل الواجهة المضمّنة بين فيديو WebSocket ولقطات GitHub. هذا لا يثبت فيديو Android أو WKWebView على جهاز فعلي.

## ما لم يكتمل

- البث الذي تحقق هو لقطات متتابعة. فيديو H.264 السلس لم يثبت بعد؛ النفق المؤقت قد يتأخر أو يتعذر اتصاله.
- الرفع الخاص عبر أصول GitHub والاستعادة نجحا في اختبار التخزين؛ ما زال تدفق Files → التطبيق الكامل على iPad → جلسة Actions بحاجة لاختبار جهاز فعلي.
- تعديل APK وإعادة بنائه وتوقيعه ومقارنة طلباته مع الأصل له اختبار تكامل جديد على المحاكي، وما زال قيد التحقق. حالات اختلاف التوقيع والرجوع للأصل لها اختبارات مستقلة ناجحة.
- يلزم اختبار الحفظ الدوري/النهائي داخل جلسة Android الخاصة كاملة، إضافة إلى اختبار التخزين المستقل الناجح. المستودعات العامة ما زالت تستخدم أرشيف Actions المؤقت لمدة يوم.
- تمرير أوامر الوكيل السحابي عبر GitHub يحتاج ZEUS مفتوحًا حاليًا. وظائف التحليل التي بدأت على Actions تستمر مستقلة؛ حلقة الوكيل الكاملة في الخلفية لم تكتمل.
- مشاركة تقارير JSON/HTML/PDF موصولة بالواجهة المضمّنة عبر نتائج مشفّرة محدودة الحجم، وتحتاج تجربة واجهة المشاركة على iPad فعلي. ربط MobSF وFrida ما زال مطلوبًا.
- لم يُختبر التطبيق الكامل بهذه الإضافات على iPad فعلي، ولم تصدر IPA جديدة موثقة لهذه المرحلة.

## التشغيل والحصة

الجلسة تبدأ عند الطلب على Ubuntu قياسي، بحد15 دقيقة بعد الإقلاع وحد28 دقيقة للوظيفة كاملة.
لا يُشغّل محاكي تلقائيًا عند تعديل الشيفرة في الفرع الخاص. اختبارات Swift وبناء IPA تُشغّل عند الطلب؛ اختبارات العقود الخفيفة تعمل على Ubuntu.
المستودع الخاص يستخدم حصة Actions الخاصة بالحساب. لا توجد استضافة جديدة مدفوعة ضمن هذا المختبر.
